# 交付流程

每次完成项目改动，都必须将源码提交并推送到 GitHub 的 `main` 分支，核对远端与本地提交一致。GitHub 同步是交付的固定步骤，无需用户再次提醒。

发布新版安装包时，必须建立新的版本标签与 Release，上传对应的 JAR 和 SHA-256 文件，确认版本已正式发布且附件校验值与交付文件一致。已发布的标签不得覆盖或移动。仅修改文档时无需升级模组版本或重新发布安装包。

最终交付说明必须明确同步结果，并附上对应的 Release 或提交链接。如果同步失败，应说明尚未同步的内容与具体原因，不得将未完成同步的交付描述为全部完成。

更新日志只记录功能、修复、平衡与兼容性变化，不加入测试数量、构建结果或内部核验过程。
